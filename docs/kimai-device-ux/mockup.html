Designed around the remote session

A timer belongs where the work happens. The strip stays visible across Desktop, Terminal and Files; the editor adds billing details without obscuring the remote surface.

Three deliberately different actions

  • Stop & keep: stop recording this device and retain its elapsed work. Remote access stays connected.
  • Disconnect: end remote access now. Review appears after the final contributing connection closes.
  • Discard: explicitly exclude owned time, with scope and remote consequences shown before confirmation.

Try these walkthroughs

  1. Select No matching rule. Choose a destination, enter a description, then Start timer.
  2. Select Automatic timer, then Disconnect Desktop. Review the elapsed work or save it for later.
  3. Select Shared timer. Disconnect Desktop: Terminal keeps recording. Stop tracking this device: retained time becomes reviewable.
  4. Select Unrelated timer running, Kimai unavailable, Active-time rule, or Locked recording to inspect recovery states.
  5. In My preferences choose Centered dialog, then repeat Disconnect. Disable create permission to see the destination form simplify.
  6. Switch between light and dark, then narrow the window. On mobile the editor becomes a full-width section.

Where we draw the boundary

Manual choice applies to this recording; creating a reusable rule is a separate action. New projects and activities are progressive options. Kimai’s optional Task Management plugin is outside the core activity picker.

This is a front-end simulation. There is no remote persistence, timer accounting engine, authentication, or API integration. See the accompanying design document for the full state model, security constraints, and implementation phases.
